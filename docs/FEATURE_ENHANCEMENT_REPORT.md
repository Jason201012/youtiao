## 一、项目现状总览

### 1.1 技术架构

| 维度 | 现状 |
|------|------|
| 框架 | Flutter 3.x / Dart（`sdk >=3.3.0 <4.0.0`），Material 3 |
| 状态管理 | Provider（5 个 ChangeNotifier：Task / Focus / Theme / Habit / Onboarding） |
| 持久化 | sqflite（tasks / trash / focus_sessions / habits / check_ins，整段 JSON 存储）+ SharedPreferences |
| 提醒机制 | flutter_local_notifications + setAlarmClock + `:guard` 独立进程前台服务 + 午夜原生重置闹钟 |
| 平台通道 | 自建 `com.example.todolist/file_io`（相册写入、Downloads 写入）、APK 安装器、日历读写 |
| 测试 | 28 个测试文件，约 280+ 用例，全绿 |
| 产品边界 | **纯本地离线应用**：全部数据仅存本机，无账号、无同步、无遥测；网络仅用于应用内更新检测与 APK 下载（update.json + Gitee 直链） |

### 1.2 已实现功能清单（避免重复建设）

**任务域**：增删改查、分类（工作/生活/学习）、优先级、子任务清单、备注、自由标签、拖拽排序、多选批量删除+撤销、回收站、按日期分区（逾期/今天/未来/每天/已完成）、筛选芯片、灵活重复规则（每天/每周X/每隔N天/工作日）、提醒提前量、稍后提醒（snooze 覆盖式）、通知点击直达详情。

**录入与检索**：自然语言快速录入（日期/时间/优先级/分类/标签/重复规则解析）、全局搜索（任务+习惯分组）。

**习惯域**：打卡、热力图、连续天数统计、破纪录庆祝动效、单习惯详情与分享长图、每日提醒。

**专注域**：番茄钟循环（专注/短休/长休可配置）、自定义时长、关联任务回填时长、环境音七种多音叠加淡入淡出、墙钟推算杀后台恢复、锁屏进度通知、趋势图表、分享卡。

**回顾与激励**：周报、月报/年报、AI 小结（本地模板生成）、成就系统、连续打卡 streak。

**日历**：月/周视图、完成热力、拖拽改期、专注结束记入应用内日历、可选写入系统日历。

**数据安全**：JSON 备份/恢复（schema v3 含习惯）、CSV / Markdown 导出、原子写、导出到 Downloads。

**工程化**：Gitee update.json 应用内更新检测 + APK 流式下载安装、发版脚本自动化、引导页、Material You 动态取色、纯黑背景。

## 二、功能增强建议

> 按「价值 × 成本」排序，分为四个梯队。每条建议均标注了落点文件与实现思路，可直接作为开发任务拆解。

---

### 🥇 第一梯队：高价值 · 低成本（建议优先做）

#### A1. 自动备份 + 备份文件健康自检 ⭐强烈推荐

- **现状缺口**：备份目前完全靠用户手动操作。手机丢失/误卸载时，从未手动备份的用户会丢掉全部数据——这是本地优先应用的阿喀琉斯之踵。
- **建议方案**：
  - 每日首次启动时自动把备份 JSON 快照写入 App 私有目录 `backup/auto/YYYY-MM-DD.json`，滚动保留最近 7 份；
  - 设置页新增「自动备份」开关与「最近一次自动备份时间」展示；
  - 恢复面板中列出历史快照供一键还原；
  - 顺手做「备份完整性校验」：导入前校验 schema version 与关键字段（复用现有 `data_io.dart` 的原子写）。
- **改动落点**：[data_io.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/services/data_io.dart)、`widgets/backup_sheet.dart`、`screens/settings_screen.dart`。
- **工作量估计**：1～2 天（含测试）。

#### A2. 桌面小组件（Home Screen Widget）

- **现状缺口**：代码库中无任何 AppWidget 相关代码（已确认）。对待办类应用而言，桌面小组件是打开率提升最显著的单点功能。
- **建议方案**（分两步走）：
  - **第一步**：「今日任务」只读小组件 + 一键勾选完成——用 Android AppWidgetProvider（Kotlin）读取 SQLite 共享数据，或引入 `home_widget` 包桥接；每半小时或数据变更时刷新；
  - **第二步**：小组件上直接「快速添加任务」按钮，唤起 App 的快速录入页。
- **改动落点**：新建 `android/app/src/main/kotlin/.../TodayWidgetProvider.kt`，数据侧在 [local_database.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/services/local_database.dart) 增加导出今日列表的轻量接口（写一份 JSON 到共享文件即可，原生侧无需理解业务）。
- **注意事项**：`:guard` 进程已验证了独立进程的可靠性，小组件数据同步走文件而非跨进程 DB 访问更稳妥。

#### A3. 任务模板 / 例行清单（Template）

- **现状缺口**：重复规则只能表达「单个任务的循环」，无法表达「一组任务的组合」。典型场景如「晨间例程 = 晨读 + 锻炼 + 冥想」「周报准备 = 收集数据 + 写正文 + 发送」。
- **建议方案**：
  - 新增「模板」概念：把若干任务打包保存为模板；
  - 支持一键从模板批量创建任务（可选统一截止日偏移，如「模板创建后每天顺延」）；
  - 数据上只需一张新表或在任务 JSON 中加 `templateId` 引用，复用现有 SQLite 整段 JSON 存储模式，迁移成本极低。
- **改动落点**：[task.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/models/task.dart)、`state/task_provider.dart`、`widgets/new_task_sheet.dart`。

#### A4. 搜索增强：子任务/备注全文 + 拼音首字母匹配

- **现状缺口**：[search_index.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/services/search_index.dart) 已覆盖标题/分类/优先级/备注/标签/习惯，但：
  1. 子任务文本不在搜索范围内；
  2. 中文输入场景下搜 "bj" 或 "riBao" 无法命中「日报」——拼音首字母搜索是中文效率工具的标配体验。
- **建议方案**：
  - 把 `t.subtasks` 的 title 纳入 `_matchesTask`（一行代码级别改动）；
  - 引入纯 Dart 拼音库（如 `lpinyin`），建单时预计算标题拼音串缓存进任务 JSON 新字段 `pinyinIdx`（零运行时依赖第三方服务）；搜索时同时匹配原文与拼音串。
- **工作量估计**：半天～1 天。

### 🥈 第二梯队：高价值 · 中成本

#### B1. 统计维度补强：目标设定与完成率预测

- **现状缺口**：看板/周报/月报都是「事后统计」，缺少「事前目标」——用户没法给自己定「本周完成 20 个任务」「本周专注 10 小时」的目标并追踪达成率。
- **建议方案**：
  - 新增周目标（任务完成数、专注分钟数两个维度即可，克制不贪多）；
  - 首页「本周回顾」摘要卡增加目标进度条；
  - 周报页对比「目标 vs 实际」并给出简单趋势外推（本周节奏推算周末能否达标）。
- **改动落点**：[review.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/models/review.dart)、`widgets/review_card.dart`、`screens/review_screen.dart`。

#### B2. 专注白名单模式（深度专注锁机）

- **现状缺口**：专注计时已有锁屏进度通知与环境音，但缺少「防分心」能力——这是竞品 Forest/番茄 ToDo 的核心卖点。
- **建议方案**（渐进式）：
  - **L1（低成本）**：专注进行中检测到 App 切出时弹通知「专注中断了哦」，并在统计里记录「中断次数」；
  - **L2（中等）**：接入 Android `UsageStatsManager` 检测专注期间使用了哪些分心 App，专注结束后给出「本次分心 X 次」报告；
  - **L3（谨慎评估）**：真正的锁机需要 `ACCESSIBILITY_SERVICE` 或设备管理员权限，上架风险与用户授权成本都较高，建议 L2 验证需求后再考虑。
- **改动落点**：[focus_provider.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/state/focus_provider.dart)、`screens/focus_screen.dart`、Android 原生新增 UsageStats 查询通道。

#### B3. 数据可视化升级：专注时段分布 + 分类时间投入

- **现状缺口**：现有趋势图都是「按天时长」，回答不了两个高频问题：「我一天中什么时段效率最高？」「我在工作/生活/学习上各投入了多少时间？」
- **建议方案**：
  - 专注页新增「时段分布图」（0-24h 分桶统计各小时累计专注分钟，CustomPaint 直方图即可，项目已有大量 CustomPaint 经验）；
  - 月报新增「分类时间投入」环形图（focus_sessions 已带 taskId，join 任务表取 category 即可聚合，零新存储）。
- **改动落点**：`widgets/focus_chart.dart`、`screens/period_review_screen.dart`。

#### B4. 回收站增强：30 天自动清理 + 存储占用提示

- **现状缺口**：回收站只有手动彻底删除。随使用年限增长，软删除数据只增不减。
- **建议方案**：
  - 启动时扫描 `deletedAt` 超 30 天的任务自动清理（设置页提供开关 + 「即将永久清除 N 条」预告提示，给用户反悔窗口）；
  - 回收站页头部显示「回收站占 X 条 / 已保留 Y 天」信息。
- **改动落点**：`screens/trash_screen.dart`、[task_provider.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/state/task_provider.dart) 的 `load()` 中挂一个 `_purgeExpiredTrash()`。

### 🥉 第三梯队：锦上添花 · 差异化

#### C1. 应用锁（隐私保护）

- **现状缺口**：确认无任何生物识别/锁屏相关代码。清单类应用常含私人事务，「隐私优先」的产品定位（引导页第一屏就在讲本地优先）与应用锁能力是自洽的。
- **建议方案**：接入 `local_auth`（指纹/面部/设备凭据三选一），设置页新增「启动需要验证」开关；冷启动与后台切回（`AppLifecycleState.resumed` 且离开超阈值）时校验。Flutter 侧改动小，主要是 Android `MainActivity` 配置 `USE_BIOMETRIC` 权限。

#### C2. 局域网 / 面对面数据迁移（换机助手）

- **现状缺口**：目前备份是手动导出 JSON 文件，再靠微信/网盘中转。换机时流程繁琐，且经过第三方 App 的文件中转与「本地优先」的隐私承诺有微妙冲突。
- **定位说明**：此功能**只在两台设备之间点对点直连传数据，不经过任何服务器**（局域网内 TCP 直传或 Android Wi-Fi Direct），与「不联网」的产品边界兼容——网络接口仅用于设备间通信。
- **建议方案**：
  - 旧手机开「发送」→ 起一个临时 HTTP 服务（Dart `HttpServer` 即可，零原生依赖），展示二维码/配对码；
  - 新手机「接收」→ 扫码或手动输入局域网地址，拉取备份 JSON 后走现有恢复逻辑；
  - 复用现有备份 schema v3 与原子写恢复管线，传输层只是把「文件」换成「流」；
  - 可选更轻量版本：跳过局域网，直接走 Android 近场分享（share_plus 已在依赖中）分享备份文件到新机。
- **改动落点**：[data_io.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/services/data_io.dart)、`widgets/backup_sheet.dart`、新增 `services/migration_server.dart`。

> ⚠️ **已排除方案说明**：WebDAV / 各类云同步、远程统计等一切需要服务器的方案均不符合本项目「纯本地、无账号、不上云」的定位，本报告不做推荐。若未来用户强烈要求异地备份，也应保持「默认关闭 + 显式开启 + 密码不入库」的姿态，但当前阶段不建议投入。

#### C3. 习惯与任务联动

- **现状缺口**：任务与习惯两套体系完全并行（模型也解耦）。但真实场景存在交叉：「背单词」既是每日任务也可以是习惯打卡；习惯连续失败是否应该产生一个补救任务？
- **建议方案**（挑一个做深）：
  - 「从任务一键转习惯」：任务编辑页加「转为习惯」按钮，映射字段（title→title，repeatWeekdays→weekdays，emoji 默认 ✅）；
  - 「习惯漏卡补救」：当天 23:00 检测到某习惯未打卡且 reminderMinute 已过，发一条「还差一步就连续 N 天了」的挽留通知（复用 habit 通知 id 段）。

#### C4. 快速录入语法扩展

- **现状缺口**：[task_parser.dart](file:///e:/TRAE%20SOLO/14/youtiao/lib/services/task_parser.dart) 已支持日期/时间/优先级/分类/标签/重复，但还有高频 token 未覆盖：
  - `~`/`至` 区间：`周五~周日 出去玩` → 解析为起止（当前模型无 endDate，可先只取末日并备注区间文案）；
  - 时长 token：`看书 45分钟` → 自动填充预估时长，未来与专注预设打通；
  - 地点 token：`@公司 加班` → note 里附地点（配合未来可能的地图集成）。
- **建议**：每个 token 独立正则 + 独立测试用例，延续现有「减法式解析」设计原则，宁漏勿错。

#### C5. 多语言（i18n）基建

- **现状缺口**：全部 UI 文案硬编码中文（`supportedLocales` 也仅 zh_CN）。若未来有出海打算，越晚抽离文案成本越高。
- **建议方案**：引入 `flutter gen-l10n`，先做 zh_CN/en_US 两套；可以只覆盖高频页面（首页/设置/引导），长尾页面渐进式迁移。此事项的价值在于「早做便宜」，本身不紧急。

### 🔧 第四梯队：工程质量与技术债（伴随功能迭代持续偿还）

#### D1. CI 流水线缺失

- **现状**：仓库无 GitHub Actions / Forgejo Actions 配置，质量保障全靠本机手动跑 `scripts/check.sh`。
- **建议**：加一条最小流水线：`flutter analyze && flutter test`，PR 与主分支推送触发。Forgejo Actions 兼容 Gitea Actions 语法，用 `cimg/flutter` 类镜像即可。280 个测试用例是宝贵资产，值得让它们在每次提交时自动站岗。

#### D2. 大文件拆分

- **现状**：`home_screen.dart`、`new_task_sheet.dart`、`settings_screen.dart` 等文件体量较大（千行级），多人协作与 AI 辅助修改时的冲突面大。
- **建议**：借下次改版机会把「分区逻辑」「弹层表单区块」抽成独立 widget 文件；无需一次性重构，遵循「童子军军规」渐进改善。

#### D3. 数据层 JSON 字段膨胀治理

- **现状**：Task 序列化为整段 JSON 存单列，字段已达 18 个。好处是免迁移，代价是 SQL 层无法按字段索引/查询（搜索、统计全靠内存遍历）。
- **建议**：短期不动（当前数据量级内存遍历毫无压力）；中期若引入「归档」「依赖关系」等需要查询的特性，再考虑把高频过滤字段（status/dueDate/category）提升为独立列，写好一次性迁移脚本（项目已有 v1→v2 迁移经验，风险可控）。

#### D4. 无障碍（Accessibility）补课

- **现状**：任务行的滑动操作、图标按钮普遍缺少 Semantics 标注。
- **建议**：为交互元素补 `Semantics` / `tooltip`，跑一遍 TalkBack 走查。这也是上架 Google Play 前的必要功课。

## 三、路线图建议

结合「有条」当前的产品阶段（功能广度已经铺开，进入纵深打磨期），建议的版本节奏：

| 版本 | 主题 | 建议内容 |
|------|------|----------|
| v2.6.x | 数据安全感 | A1 自动备份 + B4 回收站自动清理 + D1 CI |
| v2.7.x | 触达效率 | A2 桌面小组件 + A4 搜索拼音增强 |
| v2.8.x | 深度专注 | B1 目标设定 + B2 白名单专注 L1/L2 |
| v3.0.x | 生态雏形 | A3 模板 + C3 任务↔习惯联动 + C2 局域网换机助手 |
| v4.0.x | 开放平台 | 扩展系统 L1→L3 渐进落地（见第四章专项设计） |

> 排序逻辑：先把「数据不会丢」这个底线承诺做扎实（自动备份），再做「触达效率」（小组件是待办应用最大的增量入口），然后才是纵深特性。i18n（C5）如果列入计划，应尽早启动文案抽离，因为它的时间成本随功能增长线性上升。

## 四、总结

「有条」目前的完成度在个人开源项目中相当突出：任务/习惯/专注/统计四条产品线齐备，ColorOS 保活、午夜重置、墙钟恢复这些「脏活累活」都处理得非常扎实，测试覆盖也很健康。后续增强的关键判断是：

1. **守住底线**：自动备份是唯一「不做会后悔」的功能；
2. **提高触达**：小组件与拼音搜索降低的是「每一次使用」的成本；
3. **克制加法**：项目一贯的「零新增存储、复用现有数据聚合」哲学值得延续——上面多数建议都刻意设计为基于现有三套数据源的派生计算，避免存储结构膨胀；
4. **坚持纯本地方位**：「数据只存你手机、无账号、不上传云端」是引导页第一屏就立下的承诺，也是相对云同步竞品最锋利的差异化卖点。所有新功能都应通过一道检验——「它需要服务器吗？」答案必须是否。本报告全部 17 条建议均已按此红线筛选，网络能力仅保留既有的应用内更新通道。

## 四、专项设计：扩展系统与开放 API（v4.0 候选）

### 4.1 可行性结论：可以做，但要选对形态

「像浏览器扩展一样」的体验 = **第三方代码 + 受控 API + 用户自主安装**。浏览器能做到动态加载 JS，是因为它自带 JS 引擎；Flutter 是 AOT 编译的，Dart 不允许运行时加载和执行任意 Dart 代码（`dart:mirrors` 在 Flutter 上被禁用，动态 `eval` 不存在）。但这不构成障碍——**在宿主 App 内嵌一个脚本解释器**即可获得同等的扩展能力，而且这恰好与「纯本地」定位完美契合：扩展完全运行在设备上、无服务器、无商店审核依赖。

三条候选路线的对比：

| 路线 | 形态 | 动态性 | 性能 | 纯本地兼容 | 风险 |
|------|------|--------|------|-----------|------|
| **R1 内嵌 JS 引擎（推荐）** | 扩展为 JS 包（manifest.json + main.js），宿主内嵌 QuickJS/FlutterJS 解释执行 | ★★★ 运行时加载 | 中（解释执行，扩展场景够用） | ✅ 完全本地 | 沙箱可控 |
| R2 进程隔离插件 | 独立 Android APK/进程，经 AIDL/Intent 与宿主通信 | ★★★ 完全独立 | 高 | ✅ 本地 | 权限治理复杂，开发门槛极高 |
| R3 静态内置「官方扩展」 | 扩展以 Dart 包形式随版本编译进主包 | ☆ 无动态性 | 最高 | ✅ 本地 | 不是真扩展，只是功能模块化 |

**推荐 R1**，理由：`flutter_js`（封装 QuickJS）或 `liquid_core` 均为纯本地方案，QuickJS 是单文件 C 引擎、已被大量嵌入式产品验证；扩展包就是一个 zip（manifest + js + 可选图标），用户从本地文件导入安装——安装动线甚至可以复用现有备份 JSON 的 file_picker 导入管线。

### 4.2 开放 API 设计（能力面）

扩展能调用的 API 通过宿主注入的桥接对象暴露（JS 侧 `ytt.api.xxx()`），按敏感度分级授权：

| 分级 | API 示例 | 说明 |
|------|----------|------|
| L0 只读 | `getTasks(filter)`, `getHabits()`, `getFocusStats(range)` | 读任务/习惯/专注聚合数据，安装时声明即可用 |
| L1 写入 | `addTask(task)`, `toggleTask(id)`, `addCheckIn(habitId)` | 弹窗告知用户扩展将写入数据 |
| L2 UI | `registerCard(slot, renderFn)`（首页/看板卡片插槽）、`registerQuickCommand(cmd)`（全局搜索/快捷指令入口） | 扩展可贡献界面区块 |
| L3 定时 | `registerCron('0 7 * * *', handler)` | 复用现有 setAlarmClock 调度唤醒扩展 |
| ❌ 不开放 | 文件系统任意读写、网络请求（默认禁用）、通知直接发送 | 守住纯本地与防骚扰底线 |

关键设计约束：
- **权限模型**照搬浏览器扩展的 manifest `permissions` 声明制：安装时逐项展示「此扩展希望读取你的任务列表」，用户逐项确认；
- **网络默认禁用**：QuickJS 里不注入任何 fetch/XHR 实现，扩展物理上无法联网——这条红线比浏览器扩展还严格，反而成为卖点（「有条扩展保证零联网」）；
- **资源限额**：单次 API 调用超时 100ms、扩展内存上限（QuickJS runtime 设 memory limit），防止劣质扩展卡死主线程；
- **崩溃隔离**：所有扩展回调包 try-catch，扩展抛错只影响自身卡片渲染，绝不拖垮宿主（沿用 main.dart `_safeLoad` 的降级哲学）。

### 4.3 扩展包格式草案

```
ytt-ext-demo/
├── manifest.json      # id / 名称 / 版本 / 权限声明 / 入口
└── main.js            # 扩展逻辑（纯 JS，无 DOM 假设）
```

```json
{
  "id": "com.example.pomodoro-report",
  "name": "番茄周报增强",
  "version": "1.0.0",
  "yttApi": "1",
  "permissions": ["tasks:read", "focus:read", "ui:card"],
  "entry": "main.js"
}
```

```javascript
// main.js —— 一个最小可用扩展示例
ytt.registerCard('home', {
  title: '本周番茄节奏',
  render() {
    const s = ytt.api.getFocusStats({ range: 'week' });
    return `${s.tomatoCount} 个番茄 · 最佳日 ${s.bestDay}`;
  }
});
```

### 4.4 分阶段落地路线

- **L1（地基，~1 周）**：内嵌 QuickJS + 桥接层 + L0/L1 只读写 API + 从文件导入 .yttext 包 + 设置页「扩展管理」（列表/启停/卸载）。先跑通「一个 JS 扩展读任务并在首页卡片显示一行字」。
- **L2（生态面，~2 周）**：UI 卡片插槽协议（registerCard 的 slot 规范）、快捷指令、权限弹窗完善、资源限额与崩溃隔离加固。
- **L3（自动化）**：cron 注册复用现有 NotificationService 调度；扩展事件订阅（onTaskCompleted 等 hook）。
- **配套**：写一份《扩展开发指南》+ 3 个示例扩展（数据导出美化器 / 自定义统计卡 / 打卡自动回复模板）；分发靠 Gitee 仓库收扩展包索引 JSON（走既有 update.json 同款 raw 直链模式，不引入服务器）。

### 4.5 与既有架构的衔接点

- 数据访问直接复用 TaskProvider/HabitProvider/FocusProvider 公开状态——扩展 API 层就是给这三个 Provider 加一层只读门面（facade），零存储改动；
- 卡片插槽：首页/看板已有成熟的分区组件体系，新增一个「扩展卡片区」容器即可；
- 安全兜底模式（try-catch 降级、persist 兜底、原子写）全部有现成范式可循；
- **风险提示**：这是全报告唯一改变产品复杂度量级的功能（引入第三方代码执行），建议放在 v3.0 之后、且 L1 验证真实需求后再投入；若最终不做，R3（把高频需求做成内置模块化「官方扩展」页签）是零风险的退路。
